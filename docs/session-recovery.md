# 游戏会话与微信授权恢复

游戏登录 Code 通常只能用于一次连接。不要把已消费的 Code 当作长期凭证反复重放。

项目可使用独立的 `session-host` 保存正在运行的游戏连接。只重启或更新 Web/业务容器时，宿主继续保持连接，业务容器启动后接管。宿主进程退出、整台服务器重启、游戏主动结束连接或账号被挤下线时，原连接仍会消失；QQ 账号可能需要重新扫码。独立宿主不是持久化 QQ 凭证，也不能保证游戏会话永远在线。

启用宿主前已消费的 Code 无法迁移到新连接；相关账号需要重新扫码一次。从此之后建立的连接才由宿主管理。不要在常规业务更新时重建宿主容器；宿主与业务容器的会话 IPC 版本必须兼容。

微信扫码如果取得完整可续期授权，服务端会按用户与游戏账号身份加密保存授权信息。运行中定期续期；连接不可用或进程启动时，符合托管条件的账号可以尝试换取新 Code。授权被撤销或无法续期时仍需扫码。旧账号须重新扫码一次，才能获得此前未保存的授权信息。删除游戏账号会清理其微信凭据，停用或到期的租户不会被自动重登。

微信凭据密文和密钥位于应用数据目录，与账号数据一同备份。密钥使用受限文件权限保存，但有服务器或备份读取权限的管理员仍可能访问授权信息，应保护服务器及备份。不要将授权数据、Code 或二维码写入日志或提交仓库。

本项目的默认 Docker Compose 已提供独立宿主。腾讯云既有定制部署可使用 `tools/tencent-session-host/install.sh`：安装前备份原配置、启动独立宿主，再配置业务容器连接本地私有套接字，并为更新脚本增加 IPC 兼容性检查。该脚本仅适用于 `/opt/services/qq-farm-classic` 的既有部署；后续正常更新继续使用该服务器的 `update.sh`。宿主镜像固定到安装时的版本，需要更新宿主时应先安排重新登录。
